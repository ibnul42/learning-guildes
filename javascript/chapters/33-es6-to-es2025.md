# Chapter 33 — ES6 → ES2025 Reference

## Learning Objectives

- Identify which ECMAScript edition introduced a given feature
- Modernise ES5-era code using the appropriate replacement
- Check real-world support before shipping a new feature
- Choose between transpiling and polyfilling

---

## 33.1 How This Chapter Works

The tables are the chapter. Each row names a feature, describes it in one line, and shows the
smallest example that makes it clear. Editions are named by year of ratification: ES2015 is ES6, and
every edition since has been an annual release.

A feature reaches the spec only after shipping in engines, so "in ES2024" means broadly available,
not brand new. Rows marked ⚠️ have partial support at the time of writing — check before shipping.

## 33.2 ES2015 (ES6) — The Big One

Everything else in this chapter is an increment. This edition changed how JavaScript is written.

| Feature | What it does | Example |
|---|---|---|
| `let` / `const` | Block scoping, TDZ, no redeclaration | `for (let i = 0; …)` gives one binding per iteration |
| Arrow functions | Concise syntax, lexical `this`, no `arguments` | `const double = n => n * 2` |
| Classes | Prototypal inheritance with declarative syntax | `class A extends B { }` |
| Template literals | Interpolation, multi-line, tagged templates | `` `Hi ${name}` `` |
| Destructuring | Extract from arrays and objects positionally or by key | `const { a, b: c = 1 } = obj` |
| Default parameters | Per-parameter defaults, evaluated at call time | `function f(a = 1, b = a * 2) {}` |
| Rest / spread | Collect and expand | `f(...args)`, `const [a, ...rest] = arr` |
| `for…of` | Iterate any iterable's values | `for (const c of 'abc')` |
| `Map` / `Set` | Keyed collections with any key type | `new Map([[obj, 'v']])` |
| `WeakMap` / `WeakSet` | Collections with weakly-held keys | `new WeakMap()` |
| `Promise` | Standardised async result | `Promise.all([a, b])` |
| `Symbol` | Unique, non-enumerable-by-default keys | `Symbol.iterator` |
| Generators | Pausable functions | `function* g() { yield 1 }` |
| Iterators | The `[Symbol.iterator]` protocol | `{ next() { return { value, done } } }` |
| Modules | `import` / `export`, static and analysable | `export default fn` |
| `Proxy` / `Reflect` | Intercept and reflect on operations | `new Proxy(t, { get() {} })` |
| Shorthand properties | `{ x }` for `{ x: x }`; `{ f() {} }` for methods | `{ x, y, sum() {} }` |
| Computed keys | Expression as a property name | `{ [key]: value }` |
| `class` getters/setters | Accessors in class bodies | `get area() { … }` |
| `Object.assign` | Shallow copy / merge own enumerables | `Object.assign({}, a, b)` |
| `Array.from` / `of` | Build arrays from iterables or arguments | `Array.from({ length: 3 }, (_, i) => i)` |
| `Array.prototype.find` / `findIndex` | First match by predicate | `arr.find(x => x > 2)` |
| `String.prototype.includes` / `startsWith` / `endsWith` / `repeat` | Substring tests without regex | `'abc'.includes('b')` |
| `Number.isNaN` / `isInteger` / `isFinite` | Non-coercing numeric checks | `Number.isNaN('x')` is `false` |
| `Math.trunc` / `sign` / `cbrt` / `hypot` | Missing maths | `Math.trunc(-4.7)` is `-4` |
| Binary / octal literals | `0b`, `0o` | `0b1010`, `0o755` |
| Typed arrays | Fixed-width binary views | `new Uint8Array(8)` |
| Tail calls | Specified; **never shipped** except in JavaScriptCore | — |

## 33.3 ES2016 and ES2017

The annual cadence begins. ES2016 is famously tiny.

**ES2016**

| Feature | What it does | Example |
|---|---|---|
| `Array.prototype.includes` | Membership test that finds `NaN` | `[NaN].includes(NaN)` is `true`; `indexOf` fails |
| `**` | Exponentiation operator | `2 ** 10` is `1024` |

**ES2017**

| Feature | What it does | Example |
|---|---|---|
| `async` / `await` | Promises with sequential syntax | `const r = await fetch(url)` |
| `Object.values` / `entries` | Own enumerable values and pairs | `Object.entries({a:1})` → `[['a',1]]` |
| `Object.getOwnPropertyDescriptors` | All descriptors, so accessors survive a copy | Enables correct `Object.create` cloning |
| `String.padStart` / `padEnd` | Pad to a length | `'5'.padStart(2, '0')` → `'05'` |
| Trailing commas in parameters | Cleaner diffs | `function f(a, b,) {}` |
| `SharedArrayBuffer` / `Atomics` | Shared memory between workers | `Atomics.add(view, 0, 1)` |

## 33.4 ES2018 and ES2019

**ES2018**

| Feature | What it does | Example |
|---|---|---|
| Object rest / spread | The pattern behind every immutable update | `const { a, ...rest } = obj` |
| `for await…of` | Iterate an async iterable | `for await (const chunk of stream)` |
| Async generators | `yield` inside `async function*` | Paginated API iteration |
| `Promise.prototype.finally` | Runs on settle, passes the result through | `.finally(() => spinner.hide())` |
| RegExp named groups | `(?<name>…)` and `match.groups` | `/(?<y>\d{4})/.exec(s).groups.y` |
| RegExp lookbehind | `(?<=…)` and `(?<!…)` | `/(?<=\$)\d+/` |
| RegExp `s` flag | `.` matches newlines | `/a.b/s` |
| RegExp `\p{…}` | Unicode property escapes (with `u`) | `/\p{L}+/u` |

**ES2019**

| Feature | What it does | Example |
|---|---|---|
| `Array.flat` / `flatMap` | Flatten by depth; map then flatten | `[[1],[2]].flat()` → `[1,2]` |
| `Object.fromEntries` | Inverse of `Object.entries` | `Object.fromEntries(map)` |
| `String.trimStart` / `trimEnd` | Directional trimming | `'  a '.trimEnd()` |
| Optional `catch` binding | Omit the parameter you don't use | `try {} catch {}` |
| `Symbol.description` | Read a symbol's description | `Symbol('x').description` |
| Stable `Array.sort` | Equal elements keep their order | Guaranteed, not implementation-defined |
| `Function.toString` revision | Returns exact source, comments included | — |
| `JSON.stringify` well-formed output | Escapes lone surrogates | Output is always valid UTF-8 |

## 33.5 ES2020 and ES2021

**ES2020**

| Feature | What it does | Example |
|---|---|---|
| Optional chaining `?.` | Short-circuit on `null`/`undefined` | `user?.address?.city`, `fn?.()`, `arr?.[0]` |
| Nullish coalescing `??` | Default only for `null`/`undefined`, not `0` or `''` | `count ?? 10` |
| `BigInt` | Arbitrary-precision integers | `9007199254740993n` |
| `Promise.allSettled` | Never rejects; reports every outcome | `[{status:'fulfilled'}, {status:'rejected'}]` |
| Dynamic `import()` | Load a module at runtime; returns a promise | `const m = await import('./x.js')` |
| `globalThis` | One name for the global object everywhere | Replaces `window`/`global`/`self` |
| `String.matchAll` | Iterator of full match objects (needs `/g`) | `[...s.matchAll(re)]` |
| `import.meta` | Module metadata | `import.meta.url` |
| `for…in` order | Specified, no longer implementation-defined | — |

**ES2021**

| Feature | What it does | Example |
|---|---|---|
| `String.replaceAll` | Replace every occurrence without `/g` | `s.replaceAll(',', '')` |
| Logical assignment | `&&=`, `||=`, `??=` — assign conditionally | `opts.retries ??= 3` |
| Numeric separators | Readable long literals | `1_000_000` |
| `Promise.any` | First fulfilment; rejects with `AggregateError` | `Promise.any([a, b])` |
| `WeakRef` / `FinalizationRegistry` | Weak single references and finalisation callbacks | `new WeakRef(obj)` |
| `Array.sort` stability | Now required by spec | — |

`??=` is the one to internalise: `opts.retries ||= 3` overwrites a deliberate `0`, and `??=` doesn't.

## 33.6 ES2022 and ES2023

**ES2022**

| Feature | What it does | Example |
|---|---|---|
| Top-level `await` | `await` at module scope | `const config = await loadConfig()` |
| Class fields | Public instance and static fields | `class A { count = 0; static VERSION = 1 }` |
| Private fields and methods | `#name`, truly inaccessible outside | `#secret = 1; #hash() {}` |
| Static blocks | Run once at class evaluation | `static { A.registry = new Map() }` |
| `Array.at` / `String.at` | Negative indexing | `arr.at(-1)` |
| `Object.hasOwn` | Safe `hasOwnProperty` | `Object.hasOwn(obj, 'k')` |
| `#x in obj` | Brand check for private fields | `static isA(o) { return #x in o }` |
| `Error.cause` | Chain errors without losing the original | `new Error('failed', { cause: err })` |
| RegExp `d` flag | Match indices per group | `re.exec(s).indices` |

**ES2023**

| Feature | What it does | Example |
|---|---|---|
| `Array.findLast` / `findLastIndex` | Search from the end | `arr.findLast(x => x.ok)` |
| `toSorted` / `toReversed` / `toSpliced` / `with` | Non-mutating array copies | `arr.toSorted((a,b) => a-b)` |
| Hashbang grammar | `#!/usr/bin/env node` is legal syntax | CLI scripts need no workaround |
| Symbols as `WeakMap` keys | Non-registered symbols permitted | `wm.set(Symbol(), v)` |

The `to*` methods work on typed arrays too, and they're the direct fix for the most common
accidental-mutation bug in JavaScript.

## 33.7 ES2024 and ES2025

**ES2024**

| Feature | What it does | Example |
|---|---|---|
| `Object.groupBy` | Group an iterable into a null-prototype object | `Object.groupBy(items, x => x.type)` |
| `Map.groupBy` | Same, into a `Map` (so keys can be objects) | `Map.groupBy(items, x => x.owner)` |
| `Promise.withResolvers` | Get `promise`, `resolve`, `reject` together | No more assigning out of the executor |
| RegExp `v` flag | Set operations and string properties in classes | `/[\p{L}--[a-z]]/v` |
| `ArrayBuffer.transfer` / `resize` | Detach and resize buffers | `buf.transfer()` |
| `Atomics.waitAsync` | Non-blocking wait on shared memory | — |
| Well-formed Unicode strings | `isWellFormed` / `toWellFormed` | `s.toWellFormed()` |

```js
// Promise.withResolvers — replaces the "deferred" pattern everyone hand-rolled
const { promise, resolve, reject } = Promise.withResolvers();
element.addEventListener('load', resolve, { once: true });
element.addEventListener('error', reject, { once: true });
await promise;
```

**ES2025**

| Feature | What it does | Example |
|---|---|---|
| `Set` methods | `union`, `intersection`, `difference`, `symmetricDifference`, `isSubsetOf`, `isSupersetOf`, `isDisjointFrom` | `a.union(b)` |
| Iterator helpers | Lazy `map`/`filter`/`take`/`drop`/`flatMap`/`reduce`/`toArray` on any iterator | `gen().filter(x => x > 1).take(5).toArray()` |
| `RegExp.escape` | Escape a string for use in a pattern | `new RegExp(RegExp.escape(input))` |
| Import attributes | Declare a non-JS module type | `import data from './d.json' with { type: 'json' }` |
| RegExp modifiers | Flags scoped to part of a pattern | `/(?i:abc)def/` |
| `Promise.try` | Start a sync-or-async call inside a promise chain | `Promise.try(fn)` |
| Float16 | `Math.f16round`, `Float16Array` | — |
| ⚠️ `Temporal` | Date/time replacement: immutable, timezone-aware, no month-0 | `Temporal.PlainDate.from('2026-08-01')` |

```js
// Iterator helpers: lazy, so this never builds an intermediate array
function* naturals() { let n = 1; while (true) yield n++; }
naturals().map(n => n ** 2).filter(n => n % 3 === 1).take(5).toArray();
// [1, 4, 16, 25, 49]

// Set operations, at last
const a = new Set([1, 2, 3]), b = new Set([2, 3, 4]);
a.intersection(b);          // Set { 2, 3 }
a.difference(b);            // Set { 1 }
a.symmetricDifference(b);   // Set { 1, 4 }
a.isDisjointFrom(new Set([9]));  // true
```

`Temporal` is the one to watch. `Date` has been broken since 1995 — mutable, zero-indexed months, no
timezone support, and a parser that differs between engines. `Temporal` fixes all of it, but it
shipped in Firefox first and remains behind flags or absent elsewhere. Use a polyfill until support
lands.

```js
// Date, for comparison
const d = new Date(2026, 7, 1);        // month 7 is August. Mutable. Local timezone, silently.

// Temporal
const date = Temporal.PlainDate.from('2026-08-01');       // month 8 is August
date.add({ months: 1 });                                   // returns a NEW PlainDate
Temporal.ZonedDateTime.from('2026-08-01T09:00[Europe/London]');
Temporal.Now.instant().toZonedDateTimeISO('Asia/Tokyo');
```

## 33.8 Checking Support, Transpiling, and Polyfilling

**Where to check:**

- [caniuse.com](https://caniuse.com) — browser support tables with usage percentages
- MDN's browser-compatibility table on every feature page (generated from the same `browser-compat-data` as caniuse)
- [node.green](https://node.green) for Node
- `tc39.es/process-document` for a proposal's stage — stage 3 means "implementations expected", stage 4 means it's in the spec

**Transpiling versus polyfilling** — different problems, different tools:

| | Transpiling | Polyfilling |
|---|---|---|
| Fixes | **Syntax** the engine can't parse | **Missing APIs** at runtime |
| Examples | `?.`, `#private`, `async`, class fields | `Array.at`, `Object.groupBy`, `Promise.any` |
| Tool | Babel, SWC, esbuild, TypeScript | `core-js`, a hand-written shim |
| Cost | Larger, sometimes slower output | Bundle weight, and some APIs can't be polyfilled |

Syntax must be transpiled because a parse error kills the whole file before any polyfill could run.
APIs can be polyfilled because they're just properties. Some things can be neither — `Proxy`,
`WeakMap` semantics, and `BigInt` cannot be faithfully shimmed.

```js
// A polyfill: define it only if absent, matching the spec's semantics
Array.prototype.at ??= function (index) {
  const i = Math.trunc(index) || 0;
  const n = i < 0 ? this.length + i : i;
  return n < 0 || n >= this.length ? undefined : this[n];
};
```

Define your target once, in `browserslist`, and let every tool read it:

```json
{
  "browserslist": ["> 0.5%", "last 2 versions", "not dead", "not op_mini all"]
}
```

Babel with `useBuiltIns: 'usage'` then injects only the polyfills your code actually needs for those
targets. Re-check the target list annually — a `browserslist` written in 2019 is transpiling
`async/await` for browsers nobody uses, which costs bundle size and debuggability for nothing.

> ⚠️ **Gotcha** — `preset-env` with no explicit target defaults to transpiling for ES5, producing far
> larger and slower output than any current browser needs. Always set targets.

> 💼 **Interview** — "Which ES version introduced optional chaining?" ES2020, alongside `??` and
> `Promise.allSettled`. The pairing is worth remembering, because `?.` and `??` were designed
> together and are almost always used together.

## 33.9 Common Mistakes and Best Practices

**Mistake: `||=` where `??=` is meant.** `count ||= 10` overwrites a legitimate `0`.

**Mistake: `Promise.all` when you need every result.** One rejection discards the rest — use
`allSettled`.

**Mistake: `arr[arr.length - 1]` after ES2022.** `arr.at(-1)`, which also works on strings.

**Mistake: `obj.hasOwnProperty(k)` on a null-prototype or user-keyed object.** `Object.hasOwn(obj, k)`
can't be shadowed.

**Mistake: `new Date(...)` arithmetic.** Mutable, zero-indexed months, timezone-implicit. Use
`Temporal` with a polyfill, or a date library.

**Mistake: transpiling to ES5 in 2026.** Check your `browserslist`; the output is bigger, slower, and
harder to debug for no benefit.

**Mistake: assuming stage-3 means shipped.** Stage 3 means implementations are expected, not that any
exist. Check support, not the proposal stage.

**Best practice: prefer the non-mutating method by default.** `toSorted`, `toReversed`, `with`,
`toSpliced`.

**Best practice: use `Object.groupBy` and `Map.groupBy` instead of a `reduce`.** Shorter, clearer, and
the null prototype avoids a prototype-pollution surface.

**Best practice: set `browserslist` explicitly and revisit it yearly.** It's the single input that
determines your bundle's size and syntax level.

## 33.10 Questions

**1.** MCQ — Optional chaining arrived in: a) ES2019 b) ES2020 c) ES2021 d) ES2022
<details><summary>Answer</summary>**b)** With `??`, `BigInt`, `allSettled`, and dynamic `import()`.</details>

**2.** MCQ — `#private` fields arrived in: a) ES2015 b) ES2020 c) ES2022 d) ES2023
<details><summary>Answer</summary>**c)** Alongside top-level `await`, `at`, `Object.hasOwn`, and `Error.cause`.</details>

**3.** MCQ — Which edition gave us `toSorted`? a) ES2021 b) ES2022 c) ES2023 d) ES2024
<details><summary>Answer</summary>**c)** With `toReversed`, `toSpliced`, `with`, and `findLast`.</details>

**4.** MCQ — `Object.groupBy` is from: a) ES2022 b) ES2023 c) ES2024 d) ES2025
<details><summary>Answer</summary>**c)** With `Promise.withResolvers` and the RegExp `v` flag.</details>

**5.** MCQ — Set methods like `union` and `intersection` arrived in: a) ES2015 b) ES2021 c) ES2024 d) ES2025
<details><summary>Answer</summary>**d)** With iterator helpers, `RegExp.escape`, and import attributes.</details>

**6.** MCQ — Which needs transpiling rather than polyfilling? a) `Array.at` b) `Object.hasOwn` c) `#private` fields d) `Promise.any`
<details><summary>Answer</summary>**c)** It's syntax — the file won't parse, so no runtime shim can help.</details>

**7.** MCQ — `2 ** 10` was added in: a) ES2015 b) ES2016 c) ES2017 d) ES2020
<details><summary>Answer</summary>**b)** One of ES2016's two features.</details>

**8.** Short — Why does `??=` exist when `||=` already did?
<details><summary>Answer</summary>`||=` assigns when the left side is falsy, so it clobbers a deliberate `0`, `''`, or `false`. `??=` assigns only for `null` and `undefined`, which is what "supply a default" almost always means.</details>

**9.** Short — What problem does `Error.cause` solve?
<details><summary>Answer</summary>Rethrowing with context used to discard the original error's message and stack. `new Error('Failed to save', { cause: err })` preserves the chain so the root cause survives to the log.</details>

**10.** Short — Why is `Promise.withResolvers` an improvement?
<details><summary>Answer</summary>It removes the "deferred" pattern of assigning `resolve`/`reject` out of the executor into outer variables, which was ubiquitous, easy to get wrong, and untypeable without a cast.</details>

**11.** Short — What makes iterator helpers different from array methods?
<details><summary>Answer</summary>They're lazy and work on any iterator, so they never materialise an intermediate array and can operate on infinite sequences. `naturals().map(f).take(5)` terminates; the array equivalent doesn't exist.</details>

**12.** Short — Name three things `Temporal` fixes about `Date`.
<details><summary>Answer</summary>Immutability (every operation returns a new value), one-indexed months instead of zero-indexed, and first-class timezone and calendar support instead of implicit local time. A fourth is a consistent parser across engines.</details>

**13.** Short — Difference between stage 3 and stage 4 at TC39?
<details><summary>Answer</summary>Stage 3 means the spec text is complete and implementations are invited; stage 4 means it has shipped in multiple engines, passed tests, and is in the next edition. Neither guarantees the browsers *your users* have.</details>

**14.** Output —
```js
console.log([NaN].includes(NaN), [NaN].indexOf(NaN));
```
<details><summary>Answer</summary>`true -1` — `includes` uses SameValueZero, `indexOf` uses strict equality and `NaN !== NaN`.</details>

**15.** Output —
```js
let a = 0, b = 0;
a ||= 5;
b ??= 5;
console.log(a, b);
```
<details><summary>Answer</summary>`5 0` — `0` is falsy so `||=` assigned; `0` is not nullish so `??=` didn't.</details>

**16.** Output —
```js
console.log(Object.groupBy([1, 2, 3, 4], n => (n % 2 ? 'odd' : 'even')));
```
<details><summary>Answer</summary>`{ odd: [1, 3], even: [2, 4] }` — with a null prototype, so it has no `toString` or `hasOwnProperty`.</details>

**17.** Output —
```js
const a = new Set([1, 2, 3]);
console.log([...a.difference(new Set([2]))], a.size);
```
<details><summary>Answer</summary>`[1, 3] 3` — the set methods return new sets and never mutate the receiver.</details>

**18.** Output —
```js
console.log(new Date(2026, 7, 1).getMonth());
console.log(Temporal.PlainDate.from('2026-08-01').month);
```
<details><summary>Answer</summary>`7` then `8` — `Date` months are zero-indexed, `Temporal`'s are not.</details>

**19.** Debug — Code using `?.` throws `SyntaxError: Unexpected token '.'` in production but works locally.
<details><summary>Answer</summary>The production build targets an older syntax level than the local dev server, or a dependency ships untranspiled modern syntax that the bundler excluded from transpilation. Check `browserslist` and whether `node_modules` is in the Babel/SWC include set.</details>

**20.** Debug — A polyfill for `Array.prototype.at` breaks a `for…in` loop over an array.
<details><summary>Answer</summary>It was assigned with `Array.prototype.at = fn`, making it enumerable, so it appears in `for…in`. Define it with `Object.defineProperty(..., { enumerable: false, writable: true, configurable: true })`, matching the spec's attributes.</details>

**21.** Debug — `Object.groupBy` is `undefined` in a Node 18 CI runner but works locally on Node 22.
<details><summary>Answer</summary>It's an ES2024 API, added in Node 21. Either raise the CI Node version to match the local one — and pin it in `.nvmrc` and `engines` so they can't diverge again — or polyfill it.</details>

**22.** Debug — Bundle size doubled after adding one modern-syntax dependency.
<details><summary>Answer</summary>The dependency's syntax forced the bundler to transpile it for an old `browserslist` target, pulling in `core-js` helpers. Update the target to something current; if the old target is genuinely required, check whether the dependency publishes a pre-transpiled build.</details>

**23.** Code — Rewrite this ES5 code with modern syntax.
```js
var self = this;
function getNames(users) {
  var out = [];
  for (var i = 0; i < users.length; i++) {
    if (users[i] && users[i].profile && users[i].profile.name) {
      out.push(users[i].profile.name.toUpperCase());
    }
  }
  return out;
}
```
<details><summary>Answer</summary>

```js
const getNames = (users) =>
  users.flatMap(u => u?.profile?.name?.toUpperCase() ?? []);   // flatMap + [] drops misses
```
The `self = this` line disappears because an arrow function inherits `this` lexically.</details>

**24.** Code — Rewrite this callback chain with `async`/`await` and modern error handling.
```js
function load(id, cb) {
  getUser(id, function (err, user) {
    if (err) return cb(err);
    getOrders(user.id, function (err, orders) {
      if (err) return cb(err);
      cb(null, { user: user, orders: orders });
    });
  });
}
```
<details><summary>Answer</summary>

```js
async function load(id) {
  const user = await getUser(id);
  try {
    const orders = await getOrders(user.id);
    return { user, orders };
  } catch (err) {
    throw new Error(`Failed to load orders for user ${id}`, { cause: err });   // ES2022
  }
}
```
</details>

**25.** Code — Replace a `reduce`-based grouping and a manual dedupe-intersection with ES2024/2025 APIs.
<details><summary>Answer</summary>

```js
// Before
const byType = items.reduce((acc, x) => { (acc[x.type] ??= []).push(x); return acc; }, {});
const common = [...new Set(a)].filter(x => new Set(b).has(x));

// After
const byType = Object.groupBy(items, x => x.type);                    // ES2024
const common = [...new Set(a).intersection(new Set(b))];              // ES2025
```
</details>

**26.** Scenario — A team wants to adopt `Temporal` now. What do you advise?
<details><summary>Answer</summary>Adopt the *API* now behind the official polyfill, since that gives you correct date arithmetic today and a free upgrade when native support lands — the polyfill is large (tens of KB), so measure the bundle impact and consider loading it only on routes that do date maths. Don't rely on native `Temporal` yet: it's shipped in Firefox and is flagged or absent elsewhere at the time of writing. Keep the conversion at the boundary — parse into `Temporal` on input and format on output — so the eventual switch touches no business logic.</details>

**27.** Scenario — Your `browserslist` hasn't been reviewed in four years. What do you do?
<details><summary>Answer</summary>Look at your actual analytics rather than a generic query, since `> 0.5%` global usage bears no relation to your users' browsers. Set the target from real data, run `npx browserslist` to see what that resolves to, and diff the bundle before and after — dropping ES5 output typically removes a large share of the `core-js` payload and makes stack traces readable again. Add a CI check on bundle size so the win doesn't silently erode, and put a calendar reminder to revisit annually.</details>

## Chapter Summary

- ES2015 was the structural change; every edition since is an annual increment, named by ratification year.
- `??` and `?.` (ES2020) and `??=` (ES2021) replaced a decade of defensive-default idioms — and `||=` is not a substitute.
- ES2022 gave classes real privacy (`#x`) and errors real chaining (`cause`).
- ES2023's `to*` methods are the fix for accidental array mutation; prefer them by default.
- ES2024–2025 brought `Object.groupBy`, `Promise.withResolvers`, set operations, lazy iterator helpers, and `Temporal`.
- Syntax must be transpiled and APIs can be polyfilled; both are driven by `browserslist`, which needs reviewing yearly.

1. Take a 100-line ES5 file and modernise it, listing the edition each replacement came from.
2. Run `npx browserslist` on a project and identify every feature its target forces you to transpile.
3. Write spec-compliant polyfills for `Array.prototype.at`, `Object.hasOwn`, and `Promise.withResolvers`, with correct property attributes.
4. Reimplement a `reduce`-heavy data pipeline using iterator helpers and measure whether laziness changes anything at your data size.
5. Convert a module's date handling from `Date` to `Temporal` via the polyfill, and count the bugs the change exposes.

## Mini Project: A Feature-Support Dashboard

Build a page that reports which ECMAScript features the current browser supports natively.

- Detect every API-level feature in this chapter by presence, not by user-agent string
- Detect syntax-level features safely with `new Function('…')` inside a `try`, and explain in a comment why direct syntax would break the file
- Group results by edition, with a per-edition support percentage
- Show what a given failure implies: "this browser needs the `Object.groupBy` polyfill"
- Read the target list from a `browserslist` string and flag features that target doesn't cover
- Work with JavaScript disabled to the extent of showing a meaningful message
